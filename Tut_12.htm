Tutorial 12: VR Exercises (XR Interaction Toolkit)

Target setup: Unity 6000.0.58f2, OpenXR, XR Interaction Toolkit 3.0.10, and Starter Assets.

Overview

These exercises extend movement, triggers and collisions, ray interaction, and smoothing using Lerp, MoveTowards, and LookAt in a VR-first workflow.

  • Target: Any OpenXR headset
  • Locomotion: Teleport plus Continuous Move
  • Input: Action-based using Starter Assets
  • Difficulty: Intermediate beginner

Before You Start

  • OpenXR is enabled in XR Plug-in Management.
  • Scene has XR Origin (Action-based) from Starter Assets.
  • Controllers include at least one XR Ray Interactor.
  • Locomotion providers are present: Teleportation Provider and Continuous Move Provider, plus a turn provider.
Comfort note: Snap Turn is recommended as a default, as continuous turning can cause discomfort for some users.

Exercise 1: Trigger-Controlled Sliding Door (Hand Only)

Build a kinematic sliding door that opens only when a hand collider enters the trigger zone.

Requirements

  1. Create a Door object with collider and kinematic Rigidbody.
  2. Create a separate Trigger Zone using a BoxCollider with Is Trigger enabled.
  3. Move the door using Vector3.MoveTowards or a lerp-over-time pattern.
  4. Ensure opening logic only responds to hand objects.

Hand-Only Detection Approaches

  • Tag-based: check other.CompareTag("PlayerHand").
  • Layer-based: put hand colliders on a Hands layer.
  • Component-based: use a marker component such as HandMarker.
Troubleshooting: If trigger callbacks do not fire, ensure at least one colliding object has a Rigidbody.

Exercise 2: Ray Hover Highlight (XR Ray Interactor)

Highlight objects while the controller ray hovers over them, then restore their original look on hover exit.

Requirements

  1. Use an XR Ray Interactor pipeline for hover behavior.
  2. Apply highlight on hover enter, not only on select/grab.
  3. Restore original color or material on hover exit.

Hints

  • Use XR Interaction events on interactables for hover entered and exited.
  • Or poll current ray hit and track target changes if you need advanced control.

Exercise 3: Locomotion Mode Toggle UI (Teleport / Continuous)

Create a world-space UI panel that lets users toggle locomotion modes at runtime.

Requirements

  1. Create a world-space Canvas usable with ray-based UI interaction.
  2. Add controls for Teleport enabled/disabled and Continuous Move enabled/disabled.
  3. Enable/disable locomotion providers safely at runtime.
Comfort note: If both modes are enabled, define and document clear behavior for priority.

Exercise 4: VR-Safe LookAt (Yaw Only Billboard)

Make a label or panel face the user using Y-axis rotation only, avoiding vertical tilt.

Requirements

  1. Get the HMD/camera transform from XR Origin.
  2. Project look direction onto horizontal plane.
  3. Apply yaw-only rotation with Quaternion.LookRotation.

Example

// dir = hmd.position - label.position
// dir.y = 0
// if dir != Vector3.zero:
//     label.rotation = Quaternion.LookRotation(dir)
Why yaw only: Constantly matching pitch can feel uncomfortable and unnatural in VR UI.
