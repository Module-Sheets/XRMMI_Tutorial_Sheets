Lerp in Unity (Unity 6000.0.58f2) with XR Interaction Toolkit (XRIT 3.0.10)

Target setup: Unity 6000.0.58f2, OpenXR, XR Interaction Toolkit 3.0.10, and Starter Assets.

Linear interpolation ("lerp") is a standard technique for smoothly blending between two values. In Unity, you commonly use:

  • Mathf.Lerp(a, b, t) for floats
  • Vector3.Lerp(a, b, t) for positions/directions
  • Color.Lerp(a, b, t) for colors
  • Quaternion.Lerp(a, b, t) for rotations (often better: Quaternion.Slerp)

Core idea: the t parameter

Lerp uses a t parameter, usually in the range [0, 1]:

  • t = 0 gives the start value
  • t = 1 gives the end value
  • t = 0.5 gives a halfway blend
Important: Unity's Lerp methods clamp t to [0,1] in many cases (e.g., Color.Lerp, Vector3.Lerp). If you want extrapolation beyond the endpoints, use the *LerpUnclamped variants (e.g., Mathf.LerpUnclamped).

Setup (XRIT context)

This tutorial assumes you have:

  • An XR scene with an XR Origin (Action-based) and controllers set up using XRIT 3.x
  • Some interactable objects in the scene
Note: None of the examples below require deep XRIT APIs. We'll just use XR transforms (like the controller or HMD) as "targets" to drive t, positions, colors, and UI.

Example 1 — Material colour changes with proximity (Color.Lerp)

Goal: An object smoothly changes from farColor to nearColor as the user's hand/controller approaches it.

Scene steps

  1. Create a Cube (or any mesh) and assign a material.
  2. Drag your controller transform (e.g., RightHand Controller) into the script's proximitySource.
  3. Attach this script to the object whose material should change.
using UnityEngine;

public class ProximityColorLerp : MonoBehaviour
{
    [Header("Proximity Source (e.g., XR controller transform)")]
    [SerializeField] private Transform proximitySource;

    [Header("Distances (meters)")]
    [SerializeField] private float nearDistance = 0.15f;
    [SerializeField] private float farDistance  = 1.00f;

    [Header("Colors")]
    [SerializeField] private Color farColor  = new Color(0.2f, 0.6f, 1.0f, 1f);
    [SerializeField] private Color nearColor = new Color(1.0f, 0.2f, 0.2f, 1f);

    [Header("Material")]
    [SerializeField] private Renderer targetRenderer;

    // Optional: choose which color property to set
    [SerializeField] private string colorProperty = "_BaseColor"; // URP Lit uses _BaseColor

    private Material _mat;

    private void Awake()
    {
        if (!targetRenderer) targetRenderer = GetComponent<Renderer>();
        // Instantiate so we don't edit a shared material asset at runtime
        _mat = targetRenderer.material;
    }

    private void Update()
    {
        if (!proximitySource || !_mat) return;

        float d = Vector3.Distance(proximitySource.position, transform.position);

        // Convert distance to a 0..1 "closeness" t:
        // d <= nearDistance => t = 1
        // d >= farDistance  => t = 0
        float t = Mathf.InverseLerp(farDistance, nearDistance, d);

        // Blend color
        Color c = Color.Lerp(farColor, nearColor, t);

        _mat.SetColor(colorProperty, c);
    }
}
Why InverseLerp? Mathf.InverseLerp(a, b, value) maps a value to 0..1. Here we intentionally swap a and b so that closer distance becomes larger t.

Example 2 — Smoothly move an object to the user's hand (Vector3.Lerp)

Goal: When you press a key (desktop test) or flip a boolean (you can wire this to an XR input event later), an object "homes" toward the controller smoothly instead of teleporting.

Scene steps

  1. Create a small sphere (the follower object) and place it in front of the XR Origin.
  2. Assign the controller transform as target.
  3. Press F in Play Mode to toggle follow on/off (simple test trigger).
using UnityEngine;

public class SmoothFollowLerp : MonoBehaviour
{
    [SerializeField] private Transform target;  // e.g., XR controller
    [SerializeField] private float followSpeed = 8f; // higher = snappier
    [SerializeField] private Vector3 positionOffset = new Vector3(0, 0, 0);

    [Header("Test toggle (replace with XR input later)")]
    [SerializeField] private bool followEnabled = true;

    private void Update()
    {
        if (Input.GetKeyDown(KeyCode.F))
            followEnabled = !followEnabled;

        if (!followEnabled || !target) return;

        Vector3 desired = target.position + positionOffset;

        // Convert speed to a frame-rate independent lerp factor.
        // This is a common pattern: t = 1 - exp(-k * dt)
        float t = 1f - Mathf.Exp(-followSpeed * Time.deltaTime);

        transform.position = Vector3.Lerp(transform.position, desired, t);
    }
}
Why not use t = followSpeed * Time.deltaTime? You can, but it depends on framerate and can overshoot 1. The exponential form keeps the feel consistent across frame rates and avoids needing to clamp.

Example 3 — Smooth "fill" UI feedback for grab distance (Mathf.Lerp)

Goal: A world-space UI bar smoothly fills as your controller gets close to an object. This is useful in XR to communicate "you're in range to interact."

Scene steps

  1. Create a Canvas set to World Space.
  2. Add a UI Image set to Filled (Type: Filled, Fill Method: Horizontal).
  3. Put the Canvas near the object, or make it a child of the object.
  4. Assign the Image to fillImage and the controller to proximitySource.
using UnityEngine;
using UnityEngine.UI;

public class ProximityFillBar : MonoBehaviour
{
    [SerializeField] private Transform proximitySource; // XR controller
    [SerializeField] private Transform targetObject;    // object we're approaching

    [Header("Distances (meters)")]
    [SerializeField] private float nearDistance = 0.20f;
    [SerializeField] private float farDistance  = 1.20f;

    [Header("UI")]
    [SerializeField] private Image fillImage; // Image.type = Filled

    [Header("Smoothing")]
    [SerializeField] private float uiSmoothSpeed = 10f;

    private float _currentFill; // 0..1

    private void Update()
    {
        if (!proximitySource || !targetObject || !fillImage) return;

        float d = Vector3.Distance(proximitySource.position, targetObject.position);

        // Raw target fill (0 far .. 1 near)
        float targetFill = Mathf.InverseLerp(farDistance, nearDistance, d);

        // Smooth the displayed fill
        float t = 1f - Mathf.Exp(-uiSmoothSpeed * Time.deltaTime);
        _currentFill = Mathf.Lerp(_currentFill, targetFill, t);

        fillImage.fillAmount = _currentFill;
    }
}

Common mistakes (quick checklist)
  • Confusing "percentage" with "per second": Lerp's t is not automatically time-based. If you want "move there in 0.5 seconds," you must compute t from elapsed time.
  • Calling Lerp with a constant t each frame: If you do pos = Lerp(start, end, 0.1f) every frame but keep start constant, it will not animate. Use the current value as the start (like the examples), or use elapsed-time interpolation.
  • Editing shared materials: If you change renderer.sharedMaterial you may edit the asset for all objects. Use renderer.material (creates an instance) for per-object runtime changes.

Adjustments to try
  1. Modify Example 1 so the object also scales up when the controller is near (use Vector3.Lerp on transform.localScale).
  2. In Example 2, add rotation smoothing toward the controller using Quaternion.Slerp.
  3. In Example 3, change the fill color from green (far) to red (near) using Color.Lerp on the Image color.
