Buttons: Direct Button Access in Unity XR (OpenXR)

Tutorials for Unity 6000.0.58f2 with XR Interaction Toolkit 3.0.10, assuming a Starter XR Rig (XR Origin / Action-based).

Overview and Assumptions

Assumption: You are using OpenXR with XR Interaction Toolkit Starter Assets, usually with XR Controller (Action-based) and Input System.

Quick Decision Guide

  • Option 1 (Action-based XRI): best default and aligned with Starter rig.
  • Option 3 (Input System direct): great for extra gameplay buttons without touching Select/Activate.
  • Option 4 (Raw InputDevice): useful for diagnostics and raw values.
  • Option 2 (Device-based XRI): works but usually less flexible across OpenXR profiles.

1) Action-Based XRI Recommended

Goal

Read a controller button via the existing XR Controller (Action-based) in the Starter rig.

Steps

  1. Find a hand object under XR Origin (for example RightHand Controller).
  2. Confirm it has XR Controller (Action-based).
  3. Choose an action such as Select, Activate, or UI Press.
  4. Attach script and assign the controller reference in Inspector.

Script

using UnityEngine;
using UnityEngine.InputSystem;
using UnityEngine.XR.Interaction.Toolkit;

public class ReadXRIActionBased : MonoBehaviour
{
    [SerializeField] XRController controller;

    void Update()
    {
        if (controller == null) return;

        InputAction action = controller.activateAction.action;

        if (action != null && action.WasPressedThisFrame())
        {
            Debug.Log("Activate pressed this frame (Action-based XRI).");
        }
    }
}

Notes

  • This stays consistent with rig bindings and interaction setup.
  • Switch to controller.selectAction.action if needed.

2) Device-Based XRI

Goal

Use XR Controller (Device-based) and read controller features rather than Input Actions.

Steps

  1. Create or select a test object under XR Origin.
  2. Add XR Controller (Device-based).
  3. Configure trigger, grip, and buttons as needed.
  4. For reliable raw reads in OpenXR, query device state directly (Option 4).
Exact access patterns can differ by XRIT version and setup, so raw InputDevice checks are often used for direct state reads.

When to Use

  • Quick prototypes
  • Minimal Input System setup

Tradeoffs

  • Usually less flexible than action-based mappings across OpenXR profiles.

3) Input System Direct

Goal

Create your own Input Action such as PrimaryButton without changing XRI Select/Activate actions.

Steps

  1. Create Input Actions asset.
  2. Create Action Map Gameplay.
  3. Create button action PrimaryButton.
  4. Add bindings like <XRController>{RightHand}/primaryButton.
  5. Assign an InputActionReference to your script.

Script

using UnityEngine;
using UnityEngine.InputSystem;

public class ReadInputSystemDirect : MonoBehaviour
{
    [SerializeField] private InputActionReference primaryButton;

    private void OnEnable()
    {
        if (primaryButton != null)
            primaryButton.action.Enable();
    }

    private void OnDisable()
    {
        if (primaryButton != null)
            primaryButton.action.Disable();
    }

    void Update()
    {
        if (primaryButton != null && primaryButton.action.WasPressedThisFrame())
            Debug.Log("Primary button pressed (Input System direct).");
    }
}

Notes

  • Good for pause/menu/flashlight style actions.
  • Portable under OpenXR when bindings include sensible fallbacks.

4) Raw XR Device State (InputDevice / XRNode)

Goal

Query raw controller state directly from the OpenXR runtime.

Steps

  1. Add script to XR Origin or another scene object.
  2. Select hand with XRNode.LeftHand or XRNode.RightHand.
  3. Use TryGetFeatureValue for button and axis values.

Script

using UnityEngine;
using UnityEngine.XR;

public class ReadXRInputDevice : MonoBehaviour
{
    [SerializeField] private XRNode hand = XRNode.RightHand;

    void Update()
    {
        var device = InputDevices.GetDeviceAtXRNode(hand);
        if (!device.isValid)
            return;

        if (device.TryGetFeatureValue(CommonUsages.primaryButton, out bool primaryDown) && primaryDown)
        {
            Debug.Log($"{hand}: primaryButton is down (raw InputDevice).");
        }

        if (device.TryGetFeatureValue(CommonUsages.triggerButton, out bool triggerPressed) && triggerPressed)
        {
            Debug.Log($"{hand}: triggerButton is pressed (raw).");
        }

        if (device.TryGetFeatureValue(CommonUsages.trigger, out float triggerValue) && triggerValue > 0.8f)
        {
            Debug.Log($"{hand}: trigger axis > 0.8 (raw axis).");
        }
    }
}

Notes / Caveats

  • Not all controllers expose identical CommonUsages values.
  • Best for debugging, animation, or truly raw input needs.

What Button Do You Mean?

If needed, tailor bindings and code paths for:

  • Primary and Secondary buttons (A/X, B/Y)
  • Menu button
  • Thumbstick click vs thumbstick axis
  • Trigger press (button) vs trigger value (float)
You can combine action-based reads with a raw-device fallback when an action is not bound.
