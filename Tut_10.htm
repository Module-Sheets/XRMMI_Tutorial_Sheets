Tutorial 10: Triggers and Collisions

Summary: VR Triggers and Collision Detection
One-page summary students should memorize

Core concepts (basic, moving to XRIT-correct)

Collision vs Trigger (Unity physics)

  • Physics collisions are for dynamic rigidbodies hitting real colliders → OnCollisionEnter gives contact + impact speed.
    • Collision (OnCollisionEnter) = "bump" between non-trigger colliders, typically involving a non-kinematic Rigidbody.
  • Physics triggers are for overlap volumes → OnTriggerEnter requires actual colliders moving through space.
    • Trigger (OnTriggerEnter) = "overlap" where at least one collider has Is Trigger.

XRIT Near-Far Interactor is not physics collision detection

  • Near-Far Interactor uses casts, so near/far "contact" is best tracked via XR hover/select events, not physics callbacks.
  • Near detection is a sphere cast (query), not a physical collider pushing things.
  • Far detection is a ray/curve cast (query), not a Rigidbody collision.
  • So: Near/Far "touching" is usually communicated via XR Interaction events (hover/select), not physics callbacks.

Basic Rules translated to XR

  • If an object is moved by tracking / direct setting of pose → treat it like kinematic behavior; use overlap/queries (triggers or casts) rather than expecting collision contacts.
  • Use real collisions mainly for props that you throw/drop and that should physically strike the environment.
  • If triggers "don't work" with Near-Far, check Physics Trigger Interaction / Raycast Trigger Interaction settings on the casters.
  • If you can select through walls, it's usually layer masks / blocking configuration.

Use this rule set in VR prototypes

  • Props you throw: Rigidbody (dynamic) + non-trigger collider → collisions are meaningful (OnCollision…).
  • Zones/checkpoints: Trigger collider volumes → use OnTriggerEnter (physics overlap).
  • Near/Far interaction logic: use XR hover/select events (not triggers/collisions).
  • Near-Far Near: sphere cast radius controls usability.
  • Near-Far Far: curve/ray cast; watch for through-wall selection (layers).

1) The "3 channel" model in VR (don't mix them accidentally)

In VR you commonly have three different ways to detect interaction:

  1. XR Interaction events (recommended for Near-Far): hoverEntered, selectEntered, etc.
    • Best for: grab, poke (XR Poke Interactor), far pointing, UI-like actions.
  2. Physics Triggers (OnTriggerEnter/Exit/Stay): Overlap volumes with Is Trigger = true.
    • Best for: zones, proximity alarms, checkpoint volumes, "hand inside region", tutorial steps.
  3. Physics Collisions (OnCollisionEnter): Dynamic rigidbodies hitting colliders.
    • Best for: impact sounds, breakage thresholds, thrown-object hits.

Students should choose one channel per mechanic (e.g., grabbing = XR events; zone detection = triggers; impact = collisions).

2) "Hand triggers" need an actual physics presence

A Near-Far Interactor's near detection is a sphere cast. That does not automatically mean your hand will fire OnTriggerEnter on a trigger zone.

Recommended VR pattern: "HandSensor" collider

  • Create a small child object on each controller: HandSensor
  • Add:
    • SphereCollider (often Is Trigger OFF on the hand sensor itself; it depends on your design)
    • Rigidbody Is Kinematic = true
  • Use it for trigger zones like:
    • "hand in button volume"
    • "hand in hazard zone"
    • "hand inside snap region"

This gives you reliable physics overlap events even though your visual hand is animated/tracked.

3) Use layers aggressively (VR needs it)

Triggers can easily become noisy in VR because hands are always moving and lots of colliders overlap.

Add this best practice:

  • Put trigger zones on a Zones layer
  • Put HandSensors on a Hands layer
  • Put props on Interactables
  • Put level on Environment

Then in Project Settings > Physics (Layer Collision Matrix):

  • Enable Hands ↔ Zones
  • Disable Hands ↔ Environment (often) to reduce spam/unwanted physics
  • Decide whether Interactables ↔ Zones should count (sometimes yes for "prop entered zone", sometimes no)

This also helps with the "select through walls" problem on Near-Far by making your query/casts and physics layers align.

4) Trigger volumes in VR should be "fat" and forgiving

Users' hands jitter, tracking isn't perfect, and players approach from odd angles.

Guidelines to add:

  • Make trigger zones larger than the visible affordance (a "comfort margin").
  • Prefer simple shapes (box/sphere) over mesh triggers.
  • If it's a one-time event, use OnTriggerEnter and then disable the trigger or gate it (avoid repeated firing).

5) Debounce + state machines (essential in VR)

In VR, OnTriggerStay can fire every physics step and cause repeated actions.

Add a simple pattern:

  • On enter: set a boolean isInside = true
  • On exit: isInside = false
  • Only perform the action when state changes (edge-triggered), or add cooldown timers.

6) Triggers vs interactables: keep responsibilities separate

A common anti-pattern is making a grabbable object's collider a trigger "so I can detect overlap" and then wondering why grabbing/collisions break.

Better pattern:

  • Grabbable object colliders: non-trigger (for stable grab/throw physics)
  • Detection volumes: separate trigger colliders (child objects or separate zone objects)

7) XRIT Near-Far + triggers: two distinct "trigger" meanings

Worth adding explicitly (because students confuse this):

  • Physics trigger = Unity physics overlap callback (OnTrigger…)
  • Caster "Trigger Interaction" setting = whether Near-Far sphere/ray casts consider trigger colliders when deciding hover/select

So a trigger collider might:

  • fire OnTriggerEnter (physics), and/or
  • be hoverable/selectable by Near-Far (XR events), depending on configuration.

8) VR-specific trigger use cases to teach (good student exercises)
  • Comfort boundary: fade vignette when head/hands enter a boundary zone
  • Tutorial steps: "Place your hand in the highlighted area"
  • Snap zones: object enters zone → show ghost preview; on release inside zone → snap
  • Safety: trigger-based "do not pass" regions (hand enters hazard → haptic warning)
  • Audio: trigger zones for reverb / area ambience
