Locomotion

Target versions: Unity 6000.0.58f2, URP, XR Interaction Toolkit (XRIT) 3.0.10, OpenXR, and XR Device Simulator.

Starter Assets folder note: In XRIT 3.0.10, the sample content is versioned. You should expect paths like: Assets/Samples/XR Interaction Toolkit/3.0.10/Starter Assets/. If your project uses a different XRIT version, use the folder matching the installed version.

Overview

This document contains two short, student-friendly tutorials under a single “Locomotion” topic:

  1. Customizing XR Locomotion (disable locomotion systems and rebind controls)
  2. Lazy Navigation UI (world-space UI that follows the player with a subtle lag using Lazy Follow)

1) Customizing XR Locomotion

Introduction

The XR Interaction Toolkit Starter Assets provide a prefab that already includes multiple locomotion methods. This section shows how to:

  • Disable locomotion methods you don’t want (for example, remove teleport or snap turn).
  • Rebind locomotion inputs (useful when teaching with the XR Device Simulator).

Prerequisites

  • Packages: OpenXR, XR Interaction Toolkit (3.0.10), and the Starter Assets sample imported.
  • (Optional) XR Device Simulator for keyboard/mouse testing without a headset.

Setting up the scene

  1. Create a new scene (File > New Scene).
  2. Delete the default Main Camera (the XR Origin will provide the camera).
  3. Drag these prefabs into your scene (from Starter Assets / samples):
    • XR Interaction Setup
    • XR Device Simulator (optional)
  4. Add a teleport surface: Right-click Hierarchy > XR > Teleportation Area.
  5. Optional: assign a brighter material to the teleportation area so it’s easier to see during labs.

Disabling an entire locomotion system (XRIT 3.0.10 Starter Assets)

In XRIT 3.x Starter Assets, locomotion providers are grouped under: XR Interaction Setup > XR Origin (XR Rig) > Locomotion.

  1. In the Hierarchy, expand: XR Interaction Setup > XR Origin (XR Rig) > Locomotion.
  2. Under Locomotion, pick the locomotion provider you want to disable. In your prefab (see screenshot), examples include:
    • Move
    • Turn
    • Teleportation
    • Climb
    • Grab Move
  3. Disable that provider’s GameObject by unchecking its Active checkbox at the top of the Inspector.
  4. Press Play and verify the locomotion method no longer works for either hand.
Troubleshooting: If locomotion still works after disabling a provider, you likely have a duplicate rig/prefab in the scene or another provider still enabled. Use Hierarchy search to locate duplicates.

Finding duplicates using Hierarchy search (t:)

In the Hierarchy search bar, type t: followed by a component type to find all objects with that component. Common examples: 

t:SnapTurnProvider
t:ContinuousTurnProvider
t:DynamicMoveProvider
t:TeleportationProvider
t:GrabMoveProvider
t:TwoHandedGrabMoveProvider
t:ClimbProvider

Rebinding controls (recommended with XR Device Simulator)

Rebinding is done through the Input System action assets used by the Starter Assets rig. This is the cleanest way to move actions (Move/Turn/Teleport/etc.) to different buttons or keys.

  1. Locate the Input Actions asset used by your XR Interaction Setup rig (Starter Assets / XRI input actions).
  2. Open the asset in the Input Actions editor.
  3. Find the locomotion-related action map(s) (commonly left/right locomotion maps).
  4. Select an action you want to change (examples: Move, Turn, Teleport Mode Activate, Teleport Mode Cancel).
  5. Add or edit bindings for:
    • XR controller inputs (OpenXR)
    • XR Device Simulator bindings (keyboard/mouse)
  6. Save the Input Actions asset.
  7. Press Play and test the new binding with the simulator (for example, try moving teleport to a new keyboard key).

Practical teaching tip: if you want students to focus on one locomotion method, disable the others at the provider level (Move/Turn/Teleportation/Climb/Grab Move) so there’s no “accidental” mode switching mid-lab.

2) Lazy Navigation UI (Overlay-style UI in VR)

Introduction

In XR, you generally avoid Screen Space - Overlay UI. Instead, use a World Space Canvas and have it follow the player. This tutorial also uses Lazy Follow so the UI feels stable and slightly damped rather than rigidly locked to the headset.

UI canvas setup (World Space)

  1. Create a Canvas (Hierarchy > Create > UI > Canvas).
  2. Add any UI elements under the Canvas (Text, Images, Buttons, etc.).
  3. Create a dedicated layer for UI (example: VR_UI) and assign the Canvas to that layer (apply to children if prompted).
  4. On the Canvas component, set Render Mode to World Space.

Lazy Follow setup

  1. Add the Lazy Follow component to the Canvas GameObject.
  2. Set Target to the XR camera on your rig (the camera driven by the XR Device Simulator).
  3. Set Target Offset to (0, 0, 2) (2 meters in front is a solid default).
  4. Set Position follow mode to Follow.
  5. Set Rotation mode to Look At.
  6. Adjust movement speed/smoothing to taste.

URP overlay rendering (camera stacking)

If you want the UI to render “on top” reliably in URP, prefer a dedicated UI camera and URP camera stacking:

  1. Select the XR Origin’s Main Camera:
    • Ensure it is a URP Base camera (Render Type = Base).
    • In Culling Mask, disable the VR_UI layer.
  2. Create a new camera GameObject named UI Camera:
    • Set Render Type = Overlay.
    • Set Culling Mask to only VR_UI.
  3. On the Base camera, add the UI Camera to the Camera Stack.
  4. Press Play and verify the UI draws correctly and follows with the Lazy Follow delay.
If you can’t find Render Type / Camera Stack: check that your project is using a URP renderer configuration that supports camera stacking.
