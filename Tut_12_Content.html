VR Exercises (XR Interaction Toolkit)

Exercises for Unity 6000.0.58f2 + OpenXR + XR Interaction Toolkit 3.0.10, using Starter Assets. These tasks extend the lecture topics (movement, triggers/collisions, ray interaction, and smoothing via Lerp/MoveTowards/LookAt) in a VR-first way.

Target: Any OpenXR headset Locomotion: Teleport + Continuous Input: Action-based (Starter Assets) Difficulty: Intermediate beginner

Before you start

  • Project uses XR Plug-in Management with OpenXR enabled.
  • Scene has an XR Origin (Action-based) rig from the XRIT Starter Assets.
  • Controllers include at least one XR Ray Interactor (and optionally XR Direct Interactor).
  • Locomotion providers are present: Teleportation Provider and Continuous Move Provider (Action-based), plus a turn provider (Snap Turn recommended).
Comfort note (VR): Prefer Snap Turn as the default turning mode. Continuous turning can cause motion sickness for some users.

Exercise 1 — Trigger-controlled sliding door (hand-only)

Build a kinematic “sliding door” that opens only when a hand collider enters the trigger zone (not when a random physics cube enters).

Requirements

  1. Create a Door object with a collider and a kinematic Rigidbody.
  2. Create a separate Trigger Zone (BoxCollider with Is Trigger enabled).
  3. Door should move using Vector3.MoveTowards or a Lerp-over-time pattern.
  4. Door opens only for “hand” objects.

Suggested “hand-only” detection approaches (pick one)

  • Tag-based: Tag your hand collider objects as PlayerHand, then check other.CompareTag("PlayerHand").
  • Layer-based: Put hand colliders on a Hands layer and use layer checks / layer masks.
  • Component-based: Add a small marker component HandMarker to hand objects and check other.GetComponentInParent<HandMarker>().

Checklist

Tip: If your trigger callbacks never fire, ensure at least one of the two colliding objects (trigger zone or hand) has a Rigidbody on it. In XR setups, the hand/controller proxy often has one (commonly kinematic).

Exercise 2 — Ray hover highlight (XR Ray Interactor)

When the controller ray points at an object, highlight it (e.g., change its material color). When the ray leaves, restore the original appearance.

Requirements

  1. Use an XR Ray Interactor (do not rely only on Physics.Raycast unless you justify it).
  2. Highlight should work on “hover” (not only on select/grab).
  3. Restore the original material/color on hover exit.

Implementation hints

  • Option A: Use XRIT interaction events on interactables (hover entered/exited).
  • Option B: Poll the ray’s current 3D hit and track changes (advanced).
Marking hint: You should demonstrate you understand the difference between XRIT’s built-in ray interaction pipeline and manual raycasting. XRIT is the default VR approach.

Exercise 3 — Locomotion mode toggle UI (Teleport ↔ Continuous)

Add a world-space UI panel that lets the user toggle between locomotion modes: Teleport Enabled vs Continuous Move Enabled.

Requirements

  1. Create a world-space Canvas that the user can interact with (ray-based UI interaction).
  2. Add two toggles or buttons:
    • Teleport ON/OFF
    • Continuous Move ON/OFF
  3. Update the locomotion providers at runtime (enable/disable components or switch action bindings).

Checklist

Comfort note: If both are enabled simultaneously, decide which “wins” and document your decision. Many apps expose one locomotion mode at a time to reduce accidental movement.

Exercise 4 — VR-safe LookAt (Yaw-only billboard)

Create a label or UI panel that always faces the user, but rotates only around the Y axis (yaw), so it doesn’t tilt up/down unnaturally.

Requirements

  1. Get the HMD/camera transform (e.g., XR Origin’s Camera).
  2. Compute a look direction projected onto the horizontal plane.
  3. Rotate the label so it faces the user without pitch/roll.

Example approach (pseudocode)

// dir = hmd.position - label.position
// dir.y = 0
// if dir != 0: label.rotation = Quaternion.LookRotation(dir)
Why yaw-only? In VR, constantly tilting UI to match head pitch can be uncomfortable and looks odd. Yaw-only “billboarding” is common for signs, name tags, and tooltips.
