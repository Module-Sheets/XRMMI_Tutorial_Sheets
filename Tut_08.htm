Part 1: Grab Interactibles Expanded

Grab Interactable Expanded

For XRIT (XR Interaction Toolkit), XR Grab Interactable is a component that allows an object to be picked up by a player using an XR Direct Interactor, XR Ray Interactor, or Near-Far Interactor.

Adding the Component

The XR Grab Interactable can be added to any object, but it needs the following components:

  • Rigidbody: added automatically if missing.
  • Collider: not added automatically; can be Box, Sphere, Mesh, etc.
  • XR Interaction Manager: can exist anywhere in the scene and is assigned automatically.

Useful Parameters

Colliders

The Colliders parameter is an array that can contain multiple collider types. You can change count using the plus/minus controls or by changing the array size directly.

Using multiple colliders is useful when users should only grab specific parts (for example, handles) instead of grabbing anywhere on the object.

Movement Type

Movement Type controls how motion from the interactor is transferred to the held object. There are three modes:

Velocity Tracking

Usually the slowest and most realistic mode. It applies velocity and angular velocity from the interactor. The object can appear to lag slightly behind the hand, and very fast movement can behave unexpectedly. Best for smaller items that should collide naturally with surfaces.

Kinematic Tracking

Similar to velocity tracking and still physics-like, but can intersect with other rigidbodies more easily. Interactor velocity and angular velocity are applied to a kinematic rigidbody.

Instantaneous Tracking

The most responsive mode. Object position/rotation is set directly to match the interactor, so there is almost no lag. It is less realistic and can pass through other objects more easily.

Throwing Modifiers

XR Grab Interactable includes physics-related parameters for controlling release and throwing behavior.

Throw On Detach

If enabled, the object inherits interactor velocity when released. If disabled, or if the rigidbody is kinematic, other throw parameters are not used.

Throw Smoothing Duration

While held, velocity and angular velocity are recorded. This value defines how much recent time is used for throw calculation. Longer durations can improve consistency but may have performance cost.

Throw Smoothing Curve

Controls weighting over the recorded velocities. This smooths the release transition and can improve throw feel, at the cost of some responsiveness.

Throw Velocity Scale

Multiplier applied to linear throw velocity. Values above 1 increase force and travel distance; values below 1 reduce both.

Throw Angular Velocity Scale

Multiplier applied to rotational throw velocity. Higher values increase spin, lower values reduce it.

Attach Transforms

Attach transforms define where the object anchors when grabbed. They can be moved to specific model parts (for example, handles) to improve grip alignment. XR Grab Interactable supports a primary and secondary attach transform. The second is used when two interactors select the same object and select mode is set to Multiple.

Gaze Configuration

Gaze configuration enables interaction via XR Gaze Interactor (typically on XR Origin). Gaze behaves similarly to ray interaction but can run continuously without visuals.

With eye tracking, gaze raycasts where the user looks. Without eye tracking, it follows the headset forward vector. In simulator workflows, field-of-view overlap can also drive interaction.

Distance Calculation Mode

This dropdown changes how interaction distance is calculated when selecting/activating the interactable.

This is useful in advanced cases, such as multi-collider objects where you want to understand which collider was used during interaction.

Part 2.1: Near-Far Interactor Overview (Replacing Direct and Ray Interactors)

This comparison focuses on basic functionality in XRIT (including XRIT 3.x where the Near-Far Interactor was introduced). "Interactor" = the thing doing the interacting (hands/controllers); "Interactable" = the object being interacted with (e.g., XR Grab Interactable, UI, etc.).

Important context: In XRIT 3.x, Near-Far Interactor is designed to reduce the need to manage separate near (direct) and far (ray) interaction components and to simplify input wiring.

Quick definitions (what each is for)

  • XR Direct Interactor: Near-field interaction (touch/reach). Typical use: grab something within arm's reach.
  • XR Ray Interactor: Far-field interaction (ray/laser pointer). Typical use: point/select/grab at a distance and UI pointing.
  • Near-Far Interactor (XRIT 3.x): A unified interactor that supports both near and far interaction modes with smoother transitions and fewer components.

Reasons to use either (practical guidance)

Use XR Direct Interactor when...

  • You want hands-on, close-range grabbing only (simple room-scale interactions).
  • You want students to clearly learn the "physical reach" interaction pattern.
  • You want minimal ray/pointer UI style interactions (or UI is handled differently).

Use XR Ray Interactor when...

  • You need distance selection (pointing at objects across the room).
  • You need a laser pointer UI workflow for world-space canvases.
  • You're building a UI-heavy XR experience (menus, panels, long-range selection).

Use Near-Far Interactor (XRIT 3.x) when...

  • You want both near grabbing and far pointing without maintaining two separate interactors per hand.
  • You want a cleaner teaching path for modern XRIT: start with a working rig and then deconstruct it.
  • You want fewer conflicts and less configuration overhead for basic rigs.

Part 2.2: Near-Far Interactor Activities

XRIT Near-Far Interactor: Student Tutorial Activities

Baseline Setup (Do Once)

  1. If not created in the Start section above, create a simple scene with a floor plane and 6-10 cubes/spheres scattered around.
  2. Add XR Grab Interactable to at least 5 objects.
  3. Ensure you have a working XR Rig (Starter Assets Prefab rig or your custom XR Origin with Near-Far Interactors).
  4. Testing without hardware: enable XR Device Simulator and confirm you can move hands/controllers.

Goal: students should be able to (a) grab near objects, and (b) point/select far objects.

1) Interaction Attach Controller - activities

Interaction Attach Controller controls how a grabbed object snaps into the hand: offset, rotation alignment, and the feel of grabbing (for example, fixed grip pose vs contact pose).

Activity 1A - Grip Pose vs Natural Grab (offset and rotation)

  1. Create 2 objects:
    • Tool A: a long cube scaled like a flashlight (for example, 0.05, 0.05, 0.25)
    • Tool B: a hammer shape (simple: cube handle + cube head)
  2. Add XR Grab Interactable to both.
  3. For each object, create an empty child transform called AttachPoint where you want the hand to grip.
  4. Assign that AttachPoint as the object's Attach Transform (on XR Grab Interactable).
  5. Test grabbing:
    • Does it align like a tool in-hand?
    • Does rotation feel correct?

Deliverable: screenshot of each tool held correctly (tool points forward, not sideways/up).

Activity 1B - Fixed Orientation Challenge (rotation constraints)

  1. Create a keycard object (thin flat cube).
  2. Set an Attach Transform so the keycard always faces the camera when grabbed.
  3. Test: rotate your hand/controller. Does the keycard remain readable?

Deliverable: short notes: what changed when using a fixed attach transform vs no attach transform?

Reflection questions

  • When is a fixed grip pose better (tools, weapons, handles)?
  • When is a natural grab point better (soft objects, physics toys)?
  • How does attach rotation affect user comfort and realism?

2) Sphere Interaction Caster - activities

Sphere Interaction Caster detects nearby interactables by casting a sphere volume. This is your near interaction detector (like a hand proximity bubble).

Activity 2A - Tuning Reach (sphere radius)

  1. Place 3 small cubes close together (a cluster) on a table or in mid-air.
  2. Open the Near-Far Interactor settings for the hand and locate Sphere Interaction Caster values (radius/distance/layers).
  3. Run tests with three radius settings:
    • Small (hard to grab unless you are precise)
    • Medium (comfortable)
    • Large (too easy / grabs the wrong thing)
  4. Record what happens when objects are close together.

Deliverable: choose a best radius and write 2-3 sentences explaining why.

Activity 2B - Precision vs Accessibility (small targets)

  1. Create two targets:
    • Small target: tiny cube (for example, scale 0.02)
    • Large target: normal cube (scale 0.2)
  2. Try to grab each target with the same sphere caster settings.
  3. Adjust caster radius until the small target is reliably grabbable without making the large target too magnetic.

Deliverable: recommended settings for accessibility mode vs precision mode.

Tip: Interaction Layer Mask mini-task

Put decorative objects on a separate layer and exclude that layer from the Sphere Interaction Caster interaction mask. This helps prevent accidental grabbing of scenery.

3) Curve Interaction Caster - activities

Curve Interaction Caster projects a curved ray for far interactions, often similar to teleport arcs or adjusted aiming over obstacles.

Activity 3A - Straight vs Curved Aiming (user experience)

  1. Set up two far-interaction modes (or two hands):
    • Mode 1: straight ray (if available in your rig configuration)
    • Mode 2: Curve Interaction Caster enabled
  2. Place targets at different heights:
    • One on the floor
    • One on a shelf (above head height)
    • One behind a low obstacle (for example, a short wall)
  3. Test selecting/grabbing each target in both modes.

Deliverable: short comparison: when does curved aiming feel better or worse?

Activity 3B - Arc Tuning Challenge (curve parameters)

  1. Create a target hoop (ring made of cubes) 4-6 meters away.
  2. Adjust curve settings so the arc lands naturally on the target without excessive overshoot.
  3. Try at least three configurations:
    • Short arc (drops quickly)
    • Long arc (travels far)
    • Balanced arc (usable in most cases)

Deliverable: best curve settings plus a screenshot of the arc landing on the hoop.

Activity 3C - Far Interaction Rules (what can be selected?)

  1. Create three objects:
    • Interactable: has XR Grab Interactable
    • UI: world-space canvas button
    • Non-interactable: plain cube (no XR components)
  2. Test curved ray:
    • Which objects highlight?
    • Which can you select/grab?
  3. Change interaction layer masks so only intended targets respond.

Deliverable: rules list: Our far ray should interact with ___ but ignore ___.

Wrap-up: What students should understand

Component Student takeaway
Interaction Attach Controller How should the object sit in the hand? (offset, rotation, consistent grip poses vs natural grabs)
Sphere Interaction Caster How close do I need to be? How do we prevent grabbing the wrong thing? (radius + layers)
Curve Interaction Caster How does far selection feel? How does ray shape affect usability? (straight vs arc; tuning reach/arc)
Submit to Padlet: (1) one screenshot of a correctly gripped tool, (2) your chosen sphere radius justification, and (3) your best curve settings with a screenshot of a successful far selection.

Part 3: Hands

XR Interaction Toolkit 3.x: Add Hands as Controller Visuals (No Hand Tracking)

What this tutorial is: adding visual hand models to the rig so they follow left/right controllers.

What this tutorial is NOT: true hand tracking (skeletal hands, pinch gestures). For that, use XR Hands + the Hands Interaction Demo.

Prerequisites

  1. Unity project with OpenXR + XR Interaction Toolkit (XRIT) 3.x installed.
  2. Starter Assets sample imported (recommended, because it provides a complete rig prefab).
  3. A basic scene you can press Play on (XR Device Simulator is fine).
Tip: The easiest workflow in XRIT 3.x is to start from the Starter Assets rig prefab and swap the model.

Part 1 - Add a complete XR rig (recommended starting point)

  1. In the Project window, locate the Starter Assets rig prefab:
    • Assets/Samples/XR Interaction Toolkit/3.x.x/Starter Assets/Prefabs/
    • Prefab is typically named XR Origin (XR Rig) (name can vary slightly by version).
  2. Delete the scene's default Main Camera (if present).
  3. Drag the XR Origin (XR Rig) prefab into the scene.

Checkpoint: Press Play and confirm you can see controller visuals and move them (hardware or XR Device Simulator).

Part 2 - Identify where controller visuals live in the rig

  1. In the Hierarchy, expand your rig:
    • XR Origin (XR Rig) -> Camera Offset -> left/right controller GameObjects
  2. Click LeftHand Controller (or similar name) and look for:
    • A child object named something like Model, Controller Model, Visual, or Left Controller.
    • Or a component related to model display (for example, controller model/visuals).

Reality: XRIT rigs vary slightly by sample/version. The pattern is consistent:

  • The controller GameObject is the tracker.
  • A child GameObject holds the mesh/renderer (the visual).

Part 3 - Replace the controller model with a hand model (simple + robust)

Step 1: Import or create your hand model

  1. Bring in a hand mesh/model:
    • FBX/GLB hand model you already have, or
    • A simple placeholder (for example, a capsule + sphere) if you are testing.
  2. Make sure the hand has a Mesh Renderer (or Skinned Mesh Renderer if rigged).

Step 2: Disable or remove the old controller visual

  1. Under LeftHand Controller, find the existing model child (old controller mesh).
  2. Either:
    • Disable the Mesh Renderer (quickly reversible), or
    • Deactivate the model GameObject, or
    • Delete it (not recommended until you are sure).

Step 3: Add the hand model as a child of the controller

  1. Drag your hand model into the Hierarchy so it becomes a child of LeftHand Controller.
  2. Reset its local transform:
    • Local Position = (0, 0, 0)
    • Local Rotation = (0, 0, 0)
    • Local Scale = (1, 1, 1) (or adjust if your model imports huge/small)
  3. Rename it to something clear like LeftHandModel.

Step 4: Align the hand to match the grip pose

  1. In Scene view (not Play mode), rotate/offset the hand model so it sits naturally where the controller grip is.
  2. Common alignment work:
    • Rotate around Y by +/-90 or 180 degrees (model import axis differences)
    • Offset slightly forward on Z
    • Offset slightly down on Y
  3. Repeat the same process for the RightHand Controller.

Checkpoint: Press Play and confirm the hands move exactly with the controllers.

Part 4 - Recommended: Use a dedicated Attach transform for grabbing pose

Your hand model is only visuals. The grab point is usually controlled by an Attach Transform on the interactor (hand) and/or on the interactable (object).

  1. Under each hand/controller, create an empty child:
    • Name: GrabAttach
    • Position it where objects should snap when grabbed (usually center of palm)
    • Rotate it so forward points out of the palm (project convention dependent)
  2. On your Near-Far Interactor (or Direct Interactor), set the Attach Transform to GrabAttach (if available on your rig/interactor setup).
  3. Test: grab a cube. Does it snap naturally into the palm?

Part 5 - Optional polish (student-friendly)

  • Different materials: assign distinct materials to left vs right hand for easier debugging.
  • Hide hands during UI: optionally reduce hand visibility when ray is active (advanced/project-specific).
  • Animation: without true hand tracking, you can still animate open/close states using grip/trigger input via script or Animator.

Common issues:

  • Hands rotated wrong: model import axes differ; fix with local rotation on the model GameObject.
  • Wrong scale: adjust local scale or import settings.
  • Hands do not move: make sure the hand model is a child of the tracked controller object.
  • Grab snap feels off: configure an Attach Transform (Part 4).

Deliverables (quick student checklist)

  1. Left and right controllers show hand models (not default controller models).
  2. Hands move correctly in simulator mode.
  3. At least one object snaps naturally into the palm when grabbed (Attach Transform configured).
  4. Screenshot in Play mode showing a grabbed object held correctly.
